# FNLLA Brand Standards

Edition 2.2.0. Identity: outline. Official domain: fnlla.com.
This document supplies the copy for the visual guidebook. Its edition follows
the framework target; it does not certify or publish the software release.

## 01 | Brand Standards

A practical identity system for an AI-ready web framework with a PHP foundation and integrated developer tools.

### Build from blueprint.
FNLLA brings a structured foundation and integrated project tools to developers
building web applications. The identity should make that foundation visible:
precise marks, legible information and an orderly, useful product experience.
Blueprint means a considered plan or technical foundation: start with structure,
then build your application. It does not promise automatic code generation.

### One product. Deliberate choices.
The integrated full starter is the main FNLLA experience. Plain is an advanced
core-only option from the same framework. Neither option needs a separate logo,
colour scheme or invented product name.

### How to use this book
Use the visual examples, then the supplied masters. Outline is the only approved
signature, in blue, black, grey or white on matching blue, black and grey fields.
Edition 2.2.0 expands the kit, not the software release status.

## 03 | Positioning & Product Truth

Earn confidence through a clear product description and evidence that developers can inspect.

### Describe the actual offer
FNLLA is a web framework with a PHP foundation. Lead with project setup, private
developer access, diagnostics and controlled updates. AI-ready is a secondary
capability, not a substitute for these benefits or a claim that a model is included.
Keep FIONN AI below the primary FNLLA offer.

### Keep one identity
Use FNLLA in prose, titles and social profiles. Keep literal package names,
commands and namespaces exactly as shipped. Full and plain describe installation
choices, not competing brands. Downstream applications keep their own identity.

### Bound every claim
Do not claim universal security, enterprise certification or speed advantages
without reproducible evidence and a stated scope. A green test suite supports a
specific commit and environment; it does not prove every deployment is ready.

## 04 | FIONN AI & Connected Intelligence

Build with continuity. FIONN AI brings Persistent Personal Intelligence through a dedicated, opt-in gateway.

### FIONN AI, created by TechAyo
FIONN AI is Persistent Personal Intelligence. FNLLA's full starter includes its
gateway, not a local AI model. Access requires an appropriate FIONN developer
account, API credentials and explicit activation. The service operates separately;
installing FNLLA does not create an account or include API credit.

### Make continuity practical
Start with a non-sensitive architecture question; verify the provider and review
the answer. Account memory and permissions belong to the separate service.
FNLLA sends bounded requests with learning disabled, without automatic code
ingestion or memory writes. Explain API access and connection testing first.

### Optional API integrations
OpenAI API and Anthropic API are additional text-generation integrations,
disabled by default. They use your API key and model. Remote processing, costs
and provider policies apply. Name these APIs rather than the ambiguous cloud AI;
chat-app subscriptions do not supply API access.

## 05 | The Mark Family

One outline geometry. Six colour treatments. Preserve the space inside every letter.

### Wordmark: primary signature
Use assets/logo/wordmark.svg or assets/logo/outline/wordmark-blue.svg for the
primary signature. Letters are custom paths, not a font. Scale uniformly;
preserve every contour, the open interiors and the original proportions.

### Monogram: compact identity
Use assets/logo/monogram.svg or the matching outline/monogram-*.svg
for blue, black, grey and reversed artwork. PNG counterparts are supplied.
For browser tabs retain the dedicated assets/logo/favicon.svg.

### Reversed and neutral variants
White on Blueprint Blue is the primary reverse. White on black and grey supports
monochrome contexts. Black is #000000; grey is #6B7280, not reduced opacity.
The original outline lockup remains available as assets/logo/lockup.svg.

## 06 | Space, Scale & Integrity

Protect the mark before fitting it into a layout. Every colour treatment needs the same clear space.

### Clear space is measurable
Define H as the complete SVG viewBox height at the rendered size. Reserve at
least H/4 outside each edge; the existing artboard inset does not replace this
margin. Keep type, controls and neighbouring marks outside the protected area.

### Choose the appropriate scale
Digital minimum widths: wordmark 240 px, monogram 96 px, lockup 360 px. Use the
240 px wordmark in compact tools; below that, use the dedicated favicon or plain
FNLLA text. Dark mode uses supplied reversed artwork. Print minimums are 40, 16
and 60 mm respectively, including office templates. Proof the final output.

### Preserve the original drawing
Never stretch, rotate, thicken paths, fill the interiors or move letters. Solid
silhouettes are not part of this identity. The family plate is a reduced comparison,
not a minimum-size template for published logos.
Use supplied reversed artwork on its matching field, not CSS filters or opacity.

## 07 | Colour & Contrast

Blue identifies the brand. Neutrals carry the interface; green and red communicate outcomes, not decoration.

### Use colour by role
Blueprint Blue #2563EB marks identity, links and actions. Ink #0B1220 and Text
#374151 carry copy. Tint #EFF6FF and Binary #DCE9FC are decorative. Light grey
#F1F3F5 carries social bands with Ink text and blue accents. Use #6B7280 for
control boundaries; pale #E5E7EB only separates surfaces. Citron is retired.

### Brighter, still readable states
Use green #15803D on #F0FDF4 for success and red #D12D2D on #FEF2F2 for errors.
Both exceed 4.5:1. Pair colour with a label or familiar symbol. The full project
shell applies these semantic tokens; dark mode uses lighter text on dark fields.
Do not reuse pale background colours as body text or confuse status with branding.

### Check the actual combination
Use at least 4.5:1 for ordinary text and 3:1 for large text and required control
graphics. Ratios here assume opaque sRGB colours. Recheck after changing a
background, opacity, image or state. A pale border alone cannot define an input.

## 08 | Typography With Purpose

Two families, explicit roles and a small scale keep the brand recognisable without complicating the interface.

### Space Grotesk for the brand
Use Regular 400 for body, navigation and marketing copy; SemiBold 600 for
headings and emphasis. Product body copy starts at 16 px with 24 px line height.
Keep letter spacing at zero. Navigation labels stay in this family even when
they are links. Use only shipped weights, without synthetic bold. The browser
may slant prose emphasis because Space Grotesk has no dedicated italic face.

### JetBrains Mono for literal data
Use Regular 400 for URLs, email, code, versions, API endpoints and technical
metadata. Use SemiBold 600 for prominent fnlla.com and techayo.co.uk addresses
and the standalone FIONN AI name. Keep domains and email lowercase; preserve
case-sensitive paths. Small technical labels may use Mono; paragraphs do not.

### Match type to the surface
A 48 px heading belongs on an editorial cover; use 24-32 px page titles and
18-20 px section headings in tools. Supporting text should remain at least
14 px. Constrain line lengths and allow wrapping before reducing the font size.

## 09 | Composition & Backgrounds

One binary language: quiet microtype fields, generous clear space and neutral information bands.

### Let the work lead
Use an 8 px spacing rhythm with 4 px adjustments for controls. Use small binary
digits as a background texture, never a large standalone numeral or silhouette.
Ordinary 01 / 02 / 03 labels can give workflow steps a readable sequence. Keep
forms and data free of decoration; access screens may use a separate identity field.

### The 01 campaign field
The bytes spell FNLLA in ASCII, not live data or AI memory. Use grouped Mono
octets, #DCE9FC on white or light grey, with row breaks and fading edges. Keep
the digits small and evenly spaced, without shaping them into a second symbol.
Protect reading areas, logo clear space and QR quiet zones. Do not animate it.

### Use real visual evidence
Use light-grey information bands for social headers and repository art. Retain
blue for marks, literal addresses and small rules; print may use a strong blue
band. Diagrams explain actual boundaries, not invented UI. Keep their key claims
in adjacent Markdown and descriptive alt text. Use neutral, redacted screenshots.

## 10 | Product Surfaces

Setup, sign-in and daily tooling should feel like the same product, with clear state and predictable actions.

### Form and identity
An access screen may pair an unframed form with an identity area. Keep the
form's heading, labels, validation and recovery link together. On narrow screens,
the working form takes priority; the artwork must not push it below the fold.

### Controls communicate state
Provide default, hover, focus, loading, disabled and error states. Use established
icons and accessible names for tool actions. Keep control dimensions stable.
Use 4 px corner radii for controls and at most 8 px for genuinely framed tools.

### Preserve the user's work
Errors identify the affected field and a recovery action without clearing valid
input. Loading must not duplicate submissions. Never make recovery depend on
knowing the forgotten password. The sample is visual direction, not a working UI.

## 11 | Editorial & Social Assets

One recognisable signature across a repository, social profile and an expressive landscape print campaign.

### Open Graph
Use assets/social/open-graph.png at 1200 x 630. Keep important content at least
64 px from its edges and preserve the aspect ratio. Its wording is timeless;
add a version or release claim only when that specific release is published.

### Avatar and compact contexts
Use the dedicated LinkedIn 400 px and Facebook 1024 px square exports. Their
monograms have generous inset for circular crops. Keep slogans and release
numbers out of avatars; use covers for the broader message. Check platform cropping.

### Repository and future website
Use one README cover, one workflow diagram and one AI-boundary diagram, each
beside its matching text. Reuse the diagrams in build and AI guides. Social
covers retain the outline mark, a typed domain and a fnlla.com QR; print has
two QRs. Keep account requirements visible. A brand edition is not a release.

## 12 | Voice & Technical Examples

Write like a developer helping another developer: concrete, measured and clear about the next action.

### Say what happened
Prefer "Project created" to "Your next-generation workspace is ready".
An error should name the problem and a useful next step. Use sentence case
in interfaces. Avoid exaggerated adjectives and claims that cannot be tested.

### Use shipped syntax
Use commands from the current CLI reference. For example: php fnlla make:project
../example-app --profile=full and php fnlla route:list. Keep illustrative output
visibly separate from verified output; never invent APIs to improve a mockup.

### Keep examples neutral
Use example.com, example-app and synthetic records in published material.
Do not copy local credentials, real customer names or private paths into assets.
Keep FNLLA package identifiers and legal attribution accurate.

## 13 | Accessible Delivery

Accessibility is part of the product experience. Visual consistency cannot substitute for functional testing.

### Contrast and meaning
The colour guidance follows WCAG 2.2 contrast minimums for text and required
non-text graphics. The logo exception is not a reason to make navigation faint.
Use labels with status colours and underline inline links when colour is ambiguous.

### Focus, input and motion
Use a visible focus ring with clear separation from the control. Aim for 44 px
touch targets as a product guideline. Respect prefers-reduced-motion; optional
transitions should not carry information. Do not animate the logo on every screen.

### Validate the final context
Test keyboard order, zoom, text wrapping, validation and screen-reader names.
Give a linked logo an accessible name such as "FNLLA home"; hide duplicate
decorative marks. Review the actual viewport, not only this fixed-format PDF.

## 14 | Ownership & Handoff

Keep one maintained kit, clear provenance and an explicit distinction between guidance and shipped behaviour.

### Maintain the sources
BRAND-GUIDE.md owns the prose; tokens.json owns the visual values. Build the
PDF, print and social exports with scripts/branding/build-guide.py. Review all pages
after regeneration. The --check option detects stale committed outputs.

### Retain attribution
Use Created & maintained by TechAyo with techayo.co.uk, followed by
Lead Developer / Product Manager - Marcin Kordyaczny. Every guide page also
includes hello@techayo.co.uk. Preserve legal and font license notices.

### Review before publication
Check logo geometry, colours, type, contrast, example syntax, domain and data
privacy. Keep supporting sources linked on this page. A brand edition is not a software
release, and a design example is not a declaration of runtime compliance.
