Documentation Policy

Use neutral application names and reserved example domains. Never commit real credentials, private endpoints, customer records, local usernames, workstation paths, backup locations or access links. Keep public copyright attribution, official repository/package identifiers and actual API/configuration names accurate.

Markdown is maintained source. Rebuild registered HTML and validate hygiene:

php scripts/build-docs.php
php scripts/build-docs.php --check
php scripts/check-docs.php

Examples must match shipped commands and distinguish full-only operations. Keep compatibility in the migration guide and release history in CHANGELOG, not a growing collection of one-off upgrade files.

Operational material belongs in one place unless it describes a stable public contract. Project-facing scripts, backup policy, restore drills, release gates performance budgets and publication checks are consolidated in RELEASE-AND-OPERATIONS.md. Developer diagnostics, account recovery and technical-debt workflow are consolidated in DEVELOPER-PANEL.md.
